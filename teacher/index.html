Teacher notes

What the playground is. Real CPython running in the browser (via Pyodide) with a drop-in turtle module that draws on a canvas. Nothing is installed and no data leaves the machine. Students' code is saved in their browser's local storage per lesson, so they should use the same computer and browser to pick up where they left off, or use Copy link or Download .py to carry work around.

Differences from Thonny. input() and textinput() are not supported (a friendly message says so). Keyboard and mouse events (onkey, onclick) are accepted but do nothing. Everything else that students at this level use behaves the same, and the Download .py button adds done() so the file runs in Thonny.

Error messages. Python errors are translated into plain English with the offending line highlighted. The original Python error is always available under "Python's own words", so students still learn the real names (SyntaxError, NameError, IndentationError).

Completion checks. Each lesson has light-touch checks (listed below) that look at the code and at what was drawn. They are deliberately generous: the point is encouragement, not grading. Passing a check shows a button to the next lesson and marks the lesson with a tick in the lesson list.

Versions. The Python inside the page is Pyodide 0.28.3, which ships CPython 3.13. The status in the playground header just says "Ready to code"; hovering it shows the Pyodide version. The version is pinned in js/app.js (PYODIDE_VERSION) and in scripts/vendor_pyodide.sh.

Adding lessons. Edit js/lessons.js. Each lesson is a small object with starter code, hints, a solution and checks; the comment at the top of the file lists the check types.

What changed in the redesign

Layout. The whole workspace fits one screen with no page scrolling, on 1366×768 laptops, 1920×1080 screens, 1024-wide tablets and laptops at 125% zoom. The toolbox is now tabbed (Move, Pen, Shapes, Repeat, Other, Colours) and each lesson opens on the tab it needs. The output box has a fixed size and errors appear inside it, so the code never jumps. On narrow screens the lesson notes become a drawer behind the Lesson button; results then appear above the code. The turtle sits in the middle of the drawing from the start, and the canvas keeps its 640×480 coordinates at every size.

Readability and access. Every piece of text is at least 4.5:1 contrast, including line numbers and code comments. Every control is at least 44px, every control shows a blue focus ring, the toolbox tabs work with the arrow keys, Escape leaves the code editor, and Ctrl+Enter (Cmd+Enter on a Mac) runs the program. Nothing depends on hovering: Turbo and the text-size buttons are labelled, and toolbox help appears on click as well.

Look. Warm cream paper, one green for Run and for finished lessons, one coral for errors and Stop, and a colour per toolbox tab. Fredoka for titles and buttons, Atkinson Hyperlegible for everything children read. Buttons and toolbox chips are blocks that press down. Fonts are stored with the app, so nothing is fetched from Google.

Pip. The turtle has a face and a name (a placeholder: the children will choose it). Pip sits in the header, blinks now and then, bobs while a program runs, bounces once when it finishes, and looks puzzled (never cross) when there is an error. The same Pip is the turtle on the canvas and the face on the result banners. The passport strip in the header gains a yellow stamp with a green ring for each finished lesson or challenge; confetti falls once, the first time a lesson is completed. All of this stays still if the computer's "reduce motion" setting is on.

Checks and fixes. Every lesson and challenge was verified to open on the right tab, keep its hint button on screen, and pass with its reference solution. Two challenge solutions (Rainbow and Olympic rings) never passed before because colours used only in circles were not counted; that is fixed. The error message now puts the misspelled word in code style, and "Save picture" exports at exactly 640×480 on every screen.
